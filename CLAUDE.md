# CLAUDE.md

## What this is

**TongueUp** (French store name: *Pense Langue*) — an Expo / React Native app that reminds users to keep their tongue on the roof of their mouth (correct tongue posture / "mewing"). Users log whether their tongue was in the right place, see a chart of their history, and get periodic reminder notifications.

- Published **only on Google Play** (`com.jybenlarcher.tongueup`). iOS config exists but the app is not shipped there; don't spend effort on iOS-only behavior unless asked.
- Fully offline: no backend, no accounts. All state lives in AsyncStorage on the device.
- Supported languages: English and French.
- Support/privacy site: https://tongueup.benjylarcher.com/

## Stack

- Expo SDK 55, React Native 0.83, React 19.2 (`experiments.reactCanary: true`), Hermes, TypeScript (strict).
- Navigation: `@react-navigation/bottom-tabs` (3 tabs, no stack navigator in use).
- Notifications: `expo-notifications` + `expo-background-task` / `expo-task-manager`.
- i18n: `i18next` + `react-i18next` + `expo-localization`.
- Charts: `react-native-gifted-charts`. Icons: `@react-native-vector-icons/lucide` (font registered via the `expo-font` plugin in `app.json`).
- npm (`package-lock.json`). No test runner, linter, or formatter configured.

## Commands

```bash
npm install
npm start                  # expo start (needs a dev client; Expo Go won't run background tasks properly)
npm run android            # expo run:android — local native build, regenerates android/ via prebuild
npx tsc --noEmit           # the only static check available
eas build -p android --profile production
eas submit -p android --profile production
```

`npx tsc --noEmit` currently reports one pre-existing error in `src/utils/languageDetectorPlugin.ts` (`Localization.locale` no longer exists in expo-localization). Don't treat that as something you broke.

## Build & release notes

- `android/` is **gitignored** and generated by prebuild (CNG). Make native changes through `app.json` / config plugins, not by editing `android/` directly.
- `eas.json` uses `appVersionSource: "remote"` + `autoIncrement` for production, so EAS owns the Android `versionCode`; the `versionCode` in `app.json` is not authoritative.
- `google-services.json` is gitignored and referenced both as `android.googleServicesFile` and as the Play submit `serviceAccountKeyPath`. Never commit it. `local.properties` holds a machine-specific Android SDK path.
- Root-level `AndroidManifest.xml` (a lone `SCHEDULE_EXACT_ALARM` permission) is not wired into the build by any plugin — it has no effect.
- `store.config.json` / `store.config.ts` hold store listing metadata (`eas metadata`). `locales/*.json` are the native app-name/description localizations referenced from `app.json` (note: `locales/en.json`'s description is a stale placeholder describing a "language learning app").
- `.easignore` excludes `android/` and `ios/` so EAS does its own prebuild.
- `icon.xcf` is the GIMP source for the icon; exported images live in `assets/`.

## Architecture

Entry: `src/index.ts` → `src/App.tsx`.

`App.tsx` calls `setupTaskManager()` at module load (task definitions must be global), calls `usePushNotifications()` (permission request + Android `default` channel), then wraps everything in:

```
GestureHandlerRootView > SafeAreaProvider > SettingsProvider > ThemeProvider > SavedDataProvider > Navigation
```

Order matters: `ThemeProvider` reads from `useSettings()`.

### Tabs (`src/screens/`)
| Tab name (route) | Screen | Content |
|---|---|---|
| `Notes` | `HomeScreen.tsx` | `MomentaryNotesCard`, `PeriodicThoughtsCard`, `ProgressCard` |
| `Reminder` | `ReminderScreen.tsx` | `NotificationCard` (from `components/cards/ReminderCard.tsx`) |
| `Settings` | `SettingsScreen.tsx` | dark theme toggle, clear data, language selector |

Route names are typed in `src/types/navigation.ts` (`RootTabParamList`). `RootStackParamList` there is unused template code.

### State (`src/context/`)
- **`SettingsContext.tsx`** — `Settings` (`src/types/settings.ts`): `frequency`, `notificationsEnabled`, `quietTime {start,end}` (hours 0–23), `theme`. Persisted under `@app_tongue_patrol_settings`. Contains a small migration (`oldFrequencyToNew`) for old frequency indices.
- **`ThemeContext.tsx`** — light/dark `ThemeColors` palettes; `toggleTheme` also persists via `updateSetting('theme', …)`. Initial theme is taken from `settings.theme` at first render, i.e. before settings finish loading from storage.
- **`TimeSeriesData.tsx`** (`SavedDataProvider`, `useSavedTimeseries`) — array of `{ t, ok, nok }` persisted under `@app_tongue_timeseries_data`. `t` is **hours since epoch** (`Math.floor(Date.now()/3_600_000)`) — the "half-days" comments are outdated. On load it backfills zero points for every missing hour up to now, and seeds 12 blank hours if empty. `addPoint(ok, nok)` increments the current hour's bucket.

### Logging entries
- `MomentaryNotesCard`: one-tap "tongue on roof" (ok) / "pushing teeth / don't know" (nok).
- `PeriodicThoughtsCard`: retroactive counts (1–10) of ok/nok for times the user didn't have their phone.
- Both show a "keep up the good work" state for `TIME_NO_RECORD` (30 s) after submitting, tracked via `useAsyncStorage` keys `lastEntryRecord` / `lastPeriodicEntryRecord`.
- `ProgressCard`: two-line chart (green = ok, red = nok) over the hourly series.

### Reminders / notifications
- Confirming in `NotificationCard` calls `registerBackgroundTaskAsync()` (`src/utils/registerBackgroundNotification.ts`, `minimumInterval: 15 min`) and sets `notificationsEnabled`. Disabling unregisters it.
- The task body is in `src/background_task.ts` (`tongue_app_background_fetch`): reads settings straight from AsyncStorage, skips if less than the chosen frequency (minus `FREQUENCY_SLACK_MS`, 5 min) has passed since the last reminder, skips during quiet hours, otherwise fires an immediate local notification with translated title/body (`notification.*` keys) and records the time under `@app_tongue_last_reminder`. Registering the task resets that timestamp to now, so the first reminder comes one interval after enabling.
- **Known gaps** (be aware before changing reminder behavior):
  - The OS decides when background tasks run (≥15 min, and less often in Doze / battery saver). The chosen frequency is therefore a minimum gap between reminders, not an exact schedule.
  - Quiet hours are always applied from stored settings (default 22→8) even if the "set a quiet period" switch is off; that switch (`hasQuietTime`) is local component state and not persisted.
  - An earlier approach — pre-scheduling a batch of date-triggered notifications that skip quiet hours — lives in `src/utils/notificationScheduler.ts` and the commented-out block in `ReminderCard.tsx`. It's currently unused.
- `usePushNotifications` fetches an Expo push token but nothing uses it; there is no remote push.

### Frequencies
`src/components/FrequencySelector.tsx` exports `frequencies` (label → seconds), `FrequencyToi18n` (label → i18n key) and `frequencyHoursLimits`. **`settings.frequency` is stored as an index into `Object.keys(frequencies)`**, so reordering, inserting or removing entries silently changes users' saved choice — extend `migrateFrequency` in `SettingsContext` if you must change the list (the background task applies it too).

### Shared constants
`SETTINGS_STORAGE_KEY` and `migrateFrequency` are exported from `SettingsContext.tsx`; `BACKGROUND_FETCH_TASK` and `LAST_REMINDER_STORAGE_KEY` from `background_task.ts`. Import them rather than redefining the strings — the background task reads storage directly, outside React.

### Localization
- Translations are TS objects in `src/localization/en.ts` and `fr.ts`. `en.ts` is the typed source of truth (`src/i18next.d.ts` types `t()` keys from it), so add every new key to **both** files with the same shape.
- `src/localization.ts` initializes i18next with device locale and a custom AsyncStorage-backed detector (`utils/languageDetectorPlugin.ts`, key `settings.lang`).
- Some UI strings are still hard-coded English (e.g. the "Notes" title in `HomeScreen`, the "Data cleared" alert in `SettingsScreen`) — translate when touching them.

### Styling conventions
- No styling library. Each component builds styles with a local `createStyles(colors)` → `StyleSheet.create(...)`, memoized via `useMemo(() => createStyles(colors), [colors])`. Use `useTheme().colors` rather than hard-coded colors where possible.
- Screens (except Settings) wrap content in `ScreenWrapper` (pink `LinearGradient` over a `SafeAreaView`) with a large 42pt title header and a `ScrollView` with `gap: 25`.
- Cards use `components/Card.tsx` (`CardComponent`, `title` + `children` props).
- Shared inputs: `RollPicker` (scroll wheel, used by `FrequencySelector` and `TimeSelector`), `NumberSelector` / `LanguageSelector` (`react-native-element-dropdown`), `Button`, `ActionButton`.

### Unused / template leftovers
`src/utils/index.ts` (formatters, mock `storage`), `src/hooks/index.ts` (`useForm`, `useKeyboard`, …), the `Card`/`User`/`AppState` types in `src/types/common.ts`, and `src/utils/getDeviceId.ts` (imports `expo-application`, which is only a transitive dependency, not in `package.json`) are not used by the app.
